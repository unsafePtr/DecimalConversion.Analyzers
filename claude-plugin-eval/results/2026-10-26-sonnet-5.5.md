# Eval of the dotnet11-floating-point skill, Sonnet 5.5, 2026-10-26

The question was whether the skill makes an agent migrate code to .NET 11 better than the same agent without it.
The answer is yes, and only in one way: with the skill the agent keeps the plain cast at harmless sites, while without it the agent routes them through a helper as well.
Both arms fixed every site that .NET 11 breaks.

The raw result, with every grader verdict and each run's final message, is [2026-10-26-sonnet-5.5.json](2026-10-26-sonnet-5.5.json).

## Setup

- `claude plugin eval` 2.1.293 in WSL2 Ubuntu 26.04, against the repository root with `--eval-dir claude-plugin-eval/evals`.
- Agent model `claude-sonnet-5-5`; LLM grader on the default judge, Haiku.
- 3 runs per case and arm, 3 runs at a time, one arm with the plugin and one with no plugin.
- .NET SDK 10.0.403 and 11.0.100-rc.2 in the sandbox; the fixture's 27 tests run on net10.0 and net11.0.
- 18 agent runs in 882 seconds, $2.77 at list price including $0.01 of judge calls.

## Calibration

Run once each inside the eval, before the comparison:

| Case | Score | What it shows |
|---|---|---|
| `calibration-golden` | 1.00 | the reference fix passes every grader |
| `calibration-blanket` | 0.68 | the analyzer's fix on every site passes all 27 tests on both frameworks and fails exactly the five keep graders for the casts it rewrote |

So the tests alone cannot tell a targeted fix from a blanket one, and the keep graders can.

## Reading

Finding the breakage needs no help on this fixture.
Without the skill the agent still fixed all eight sites in every run, including the two that no test covers, and every run passed all 27 tests on both frameworks.

The skill's effect is precision.
Without it the agent sent harmless casts through a helper in 8 of 9 runs, mostly the volatility, the fill percentage and the latency log line.
Its reports justify this as keeping every result identical to .NET 10, "midpoint cases, tie ordering, formatted text", which is the blanket shift the skill exists to avoid.
In `no-op`, where nothing needs to change, it added a helper file and rewrote code in all three runs.
With the skill every harmless cast was kept in all 9 runs, and each report named the kept casts with a reason.

This is also what the analyzer's blanket DCV001 fix does, so the measured value of the skill lies in not doing that.

## Limits

- One fixture, one model, 3 runs per arm: enough to see a consistent pattern, not to put a confidence interval on it.
- The `symptom` Δ is understated by the judge. Two with-skill runs failed only the report grader, with votes of FAIL, FAIL, PASS, although their final messages give the cause, a table of changes and a "What I checked and left alone" list with a reason for each site. Counting those as passes, `symptom` is 1.00 against 0.91.
- The agent can read the tests, so the tests alone could have guided both arms; the untested sites and the keep graders are what tell them apart.
- The eval does not show the skill helping to find breakage, since the baseline already found it all; that needs a fixture where the sensitive sites are less visible.
