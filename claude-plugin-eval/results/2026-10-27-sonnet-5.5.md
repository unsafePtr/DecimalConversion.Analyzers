# Eval of the dotnet11-floating-point skill, Sonnet 5.5, 2026-10-27

This run asks two opposite things of the same solution: change only what .NET 11 needs (`migrate`), and convert every site the analyzer reports (`migrate-full`).
With the skill the agent did what each prompt asked: 9 sites changed and 6 harmless casts kept for `migrate`, all 15 sites converted for `migrate-full`.
Without the skill it converted nearly everything in both, so asking for fewer changes did not give fewer changes.
A full conversion needs little help once the analyzer is in the build: both arms did it completely in every run.

The raw result, with every grader verdict and each run's final message, is [2026-10-27-sonnet-5.5.json](2026-10-27-sonnet-5.5.json).

## What changed since the first run

- The fixture's build references the analyzer, so both arms see every site as a DCV warning, as a team that installed the package would.
- DCV004 and DCV005 are new; the fixture gained the invoice site (655.925 rounded to cents) and has 30 tests per framework instead of 27.
- The skill finds the sites through the build, suppresses kept sites when the analyzer stays in the build, and has a mode for converting every site.
- `migrate-full` and `calibration-full` are new.

Scores are therefore not directly comparable with [the first run](2026-10-26-sonnet-5.5.md), though the pattern is the same.

## Reading

The skill's effect is that the agent follows the request.
Asked to change only what needs to change, the agent without it still rewrote most harmless casts, in every `migrate` and `no-op` run and one of three `symptom` runs.
That happened although DCV001's message now says to use the helper only where the result is floored, compared, sent elsewhere as text or read for its scale, so the softer message alone does not change the behaviour.
The warnings themselves push the other way: one baseline report says it "couldn't leave these warnings in place without suppressing them", so it converted the casts, and the runs that left warnings offer to convert those too for a clean build.
With the skill the harmless casts were kept and suppressed in place with a reason in every run, and the same agent converted all of them when `migrate-full` asked it to.

A full conversion is mostly the analyzer's work.
Its warnings list every site, and its messages name the fix, down to `FloatingPoint.Normalize` for a round trip, which the baseline used in all three `migrate-full` runs.
In a spot check with the traces kept, the baseline also ran `strings` on the analyzer's code-fix DLL to recover the helper's recipe.
The skill made the full conversion a third faster and cheaper; the reports of both arms noted that the converted sites now throw on NaN or infinity.

One baseline `migrate-full` run took another route for the roundings: it reimplemented .NET 10's `Math.Round`, scaling by a power of ten, rounding and scaling back.
That reproduces .NET 10 exactly, including the midpoints .NET 10 rounded wrongly, while the decimal route the skill and the analyzer use rounds those as written.
Both pass every test, and both answer the prompt, which asked for .NET 10's results.

Neither arm ran `dotnet build` itself.
The baseline read the warnings from `TestResults/build.log` after `./test.sh`; in the spot check the skill arm read every source and test file instead, which is cheaper than a build on a solution this small.

## Limits

- One fixture, one model, 3 runs per arm: enough to see a consistent pattern, not to put a confidence interval on it.
- The fixture is small enough to read whole, so it cannot show the build finding sites that a text search misses.
- The judge is unreliable. One `symptom` baseline report failed with FAIL, FAIL, FAIL although it gives the cause, the changes and a "Checked and left alone" list with a reason for each site; counting it, `symptom` is 1.00 against 0.89.
- The `migrate-full` baseline report that failed describes the invoice rounding as still rounding in double, through its own .NET 10 `Round`; the judge read that as a site left unchanged.
- The agent can read the tests, the warnings and the analyzer package, so they guide both arms; the keep graders and the `migrate-full` summary lines are what tell the outcomes apart.
